# Mutation lab

`../tools/mutate.sh M01 --targeted --project desktop` applies one patch, copies its changed files into the running Docker dev containers, polls the HTTP-served Vite module or dashboard for a marker, records mapped tests, then reverses the patch and copies the clean files back. Without `--targeted`, all available hard scenarios run, allowing collateral detection. Expected assertion failures produce a nonzero exit; that does not mean reversal failed. Product git status must be empty after every run. Revert/sync failures retain the lock for recovery.

No compose watch process is required. `docker compose up` alone does not sync the source; `docker compose cp` updates the already-running Vite container and triggers HMR. JS uses executable metadata because Vite removes source comments. Dashboard HTML is served directly, with no backend restart. Reload success is checked through HTTP, not a fixed delay.

The runner holds `.context/locks/app.lock`, creates a random token in `app.lock/token`, and exports `APP_LOCK_TOKEN` to its scenario children. Global fault fixtures must support token-validated borrowing; borrowed release must not remove the parent's lock. T01 implemented this support under D15. run.sh now isolates per-process artifacts and holds/borrows the lock throughout browser execution and collection; every browser invocation must use this interface (D16).

Patches M01–M10/M13–M15 represent ordinary UI regressions. M11 is metadata only: the baseline already lacks org-id enforcement, so there is no guard to remove. Its evidence belongs to S10 baseline findings. M12 removes the /settings guard from the F-auth fixture, and M16 removes its Sign in button (D18). F-auth provides /login and guarded /settings, with its own clean qualification. `mutate.sh clean --base F-auth --targeted --project desktop --repeat-each=3` records that clean qualification; `mutate.sh M12 --base F-auth --targeted --project desktop` stacks the mutant. AUTH_FIXTURE=1 is set automatically. Both overlay and mutant are always reversed. M15 remains available as a patch but S14/M15 are dropped for L1 because there is no supported Cesium entity inspection surface (D19).

`build.py` deterministically generates diffs from read-only source snapshots; it never modifies product files. Apply/reverse operations are exclusively in the guarded runner. Do not regenerate patches during an active mutation.

Generate the evidence matrix with `cd qa && node --import tsx tools/matrix.ts`. A catch requires a mutant assertion failure paired with three clean passes for the same title and viewport. Baseline findings and missing/skipped/infrastructure runs are not catches. Inspect failure messages and videos before submission.

Sensitivity variants: M03b missing status defaults active; M03c grounded standby/landed/on_dock maps to in_flight in list only; M09b phone list collapses without overflow; M05b previous-selected battery stays plausible. The baseline names its grounded state standby, so M03c covers that equivalent. Variant RUN_LABELs are supported by T01 and matrix.

Full-suite evidence uses evidence/full-suite/Mxx/project/Sxx/mutant-Mxx, separate from canonical targeted proofs. full-suite.sh uses desktop for the complete scenario set, adds a phone sweep for M09/M09b, and divides each into short scenario groups, reapplying and reverting each time to keep lock holds below five minutes. Set MUTATION_PROJECTS='desktop tablet phone' for broader sweeps; collateral qualification still requires clean3 for that project. matrix.ts aggregates both sources and distinguishes collateral regressions from existing baseline findings.

T05 collect.ts is a private repeat-aware collector: stable file/title/project counters, source spec ids, failure-focused mutant canonical videos, explicit guard-context selection. It reconstructs from retained raw reports without rerunning browsers. The initial M05b bootstrap error was corrected before valid sensitivity assessment; the final patch leaves first-selection battery intact and binds subsequent battery to the previous drone.
