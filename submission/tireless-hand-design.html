FlytBase AHC · Agentic Software Testing · Level 1

Tireless Hand

A testing system that looks at the drone cockpit the way an operator does, and checks that what's on screen is true.

Most UI tests check that a button exists. We check that the screen is true.

Every check compares what the operator sees with what the system actually reports, at phone, tablet and desktop size, while we deliberately break the network, the simulator and the video.

The parts

Environment controller

Sets up the situation

Talks to the cockpit's control API: adds drones, takes off, lands, starts and stops video, injects faults, and reads the true simulator state.

Browser driver

Acts like an operator

Opens the real cockpit in Chrome, selects drones and clicks buttons, at three screen sizes. A caption on screen names each step for the video.

Oracles

Decide what "correct" means

Compare the screen with ground truth: statuses, values within tolerance, reachability, layout, safe rendering of text.

Screen contracts

List what each screen must offer

A short declarative list per screen (e.g. badge, device list, video tile, Take off, Land). One generic checker enforces it, so a removed button is caught on any screen, including new ones like a sign-in page.

Evidence recorder

Proves what happened

Every run keeps a real-time video, a screenshot, a step-by-step trace and a verdict with a plain-English failure message.

Mutation lab

Proves each test works

Plants a realistic bug in the app, reruns the tests, and confirms the right test fails. Then it removes the bug and confirms everything passes again.

What the oracles check

Each check pairs something the operator sees with an independent source of truth. The check fails only when a real operator would be misled or blocked.

Why the results can be trusted

Meaning, not pixels

Checks use names, IDs, statuses and geometry. Wording changes and a moving map don't cause false alarms.

Isolated and repeatable

Each test creates what it needs and cleans up. Anything that affects the whole app runs one at a time.

Waits for live data properly

Telemetry arrives once or twice a second, so checks poll with a time limit instead of sleeping for a fixed time.

Failures explain themselves

A failure says what the operator would experience, e.g. "Operator cannot land Drone 1: Land control missing".
